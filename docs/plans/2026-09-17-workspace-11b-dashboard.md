# Workspace 11b — Home Dashboard — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Before the pull request, review the branch with CodeRabbit only (`coderabbit:code-review`).

**Goal:** `GET /api/me/dashboard` composing the dataset totals (cached), the viewer's scope, the contributor sections (missing cells, records awaiting validation, top missing traits, contribution summary) and the curation sections (coverage, queues) for reviewers; the workspace page becomes the dashboard with the project description, quick actions and the cards of the spec.

**Architecture:** `apps/api/src/workspace/dashboard.ts` runs each section as its own small query; `stats:dataset` is cached one hour with `cachedJson`; scope-dependent numbers iterate the viewer's plot species (hundreds) through the existing indexes. The curation coverage numbers come from `coverageMetrics` — plan 11c defines the filtered version; this plan adds the unfiltered totals in `apps/api/src/dataset/coverage.ts` (`coverageTotals`), which 11c extends. The web page is a set of independent cards over one query.

**Spec:** `docs/specs/2026-09-17-workspace-design.md` §4, §7. Depends on plans 08b (plots, `me.scope`), 10a (coverage table, `cachedJson`, `forgetCached`, `ctx.redis`), 11a (contribution summary) and 09a (contest counts). Plan 10c is not needed.

### Task 4: Dashboard service and route

**Interfaces:** `getDashboard(ctx: { db; redis }, visibility, viewer: { id; permissions: ReadonlySet<PermissionKey>; scope: { plots: PlotRef[]; restricted } }): Promise<Dashboard>`; route `GET /api/me/dashboard` (`dataset.read`), mounted in `app.ts` with `app.route('/me', dashboardRoutes(ctx))` (a separate router beside `meRoutes`, whose routes are self-service; this one is permission-guarded).

- [ ] **Step 1: Failing tests** — with a plot of 3 species, 2 active traits, records on 2 cells, one confirmed and one not: `scope.speciesCount 3`, `missingCells 4`, `awaitingValidation.count 1` with the record in `records`, `topMissingTraits` ranks the trait missing on 2 species first with `missingSpeciesCount 2`; a viewer without plots: `scope null`, `missingCells null`, `awaitingValidation null`, `topMissingTraits` computed over the visible dataset (assert the trait appears with a count ≥ the plot case); `curation` null for a contributor, present for a manager with the queue counts; `dataset.speciesCount` counts active species only and is served from the cache on the second call; RFC-33: a plot-bound viewer's `awaitingValidation.records` contain only plot species.
- [ ] **Step 2: Implement** — queries: `awaitingValidation`: `itemQuery(db).where(and(speciesInViewerPlots, traitVisible, sql\`not exists (select 1 from record_annotations a where a.record_id = trait_records.id and a.kind in ('confirm', 'withdraw'))\`)).orderBy(desc(traitRecords.id)).limit(20)` plus a `count(*)` with the same `where` — the whole `contributor` section is served through `cachedJson(ctx.redis, \`dashboard:${viewer.id}\`, 300, …)` and `createRecords` / `annotateRecord` call `forgetCached(ctx.redis, \`dashboard:${actorId}\`)` after their transaction (the routes hold `ctx`; pass the call from the route, not the service, so the services stay Redis-free); `missingCells` = `plotSpecies × visibleActiveTraits − count(coverage rows on those species joined to visible active traits)`; `topMissingTraits` = for each visible active trait, `plotSpeciesCount − count(coverage rows for the trait among plot species)`, top 10 desc (no plots: `visibleActiveSpeciesCount − speciesWithData`, where `speciesWithData` per trait is `select trait_id, count(*) from species_trait_coverage c join species s on s.id = c.species_id where <speciesVisible on s> group by 1` — computed here and cached 10 minutes under `dictionary:species-counts:<u|r>`, the same key plan 10c later reuses for the dictionary's `speciesCount`). Run the sections with `Promise.all`.
- [ ] **Step 3: Commit** — `feat(api): GET /api/me/dashboard (RFC-72 R1, R2)`.
