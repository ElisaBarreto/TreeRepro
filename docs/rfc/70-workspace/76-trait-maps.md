# RFC-76 — Trait maps

| Field | Value |
|---|---|
| Status | accepted |
| Category | workspace |
| Supersedes | — |

## Context

The project publishes global maps of every trait by TDWG level-3 botanical region: the share of species with data (completeness); for a quantitative trait, statistics of the species values; for a categorical trait, the prevalence of each state. Until release v1 the owner drew them outside the platform and the platform displayed the delivered images (issues #197, #210, #211). From release v1 the platform draws them itself, from the weekly region snapshot (RFC-78 R7–R12), with the owner's map rules (`platform_package/R/platform_maps.R`), so they follow new data (epic #286, issue #293).

The maps are global aggregates, not a species' trait records, so a plot-restricted viewer sees them too (RFC-33's plot restriction is about trait records). They still sit behind login.

## Rules

- **R1** Maps are computed, never stored as images. A trait's maps are `completeness`; for a quantitative trait `mean`, `median`, `sd`, `cv`, `min` and `max`; for a categorical trait `prevalence`, one per state. Each reads the current snapshot (RFC-78 R7) of the trees view, the only view in phase 1.
- **R2** Outlines: the TDWG World Geographical Scheme for Recording Plant Distributions, level 3 (github.com/tdwg/wgsrpd, as shipped in the owner's `platform_package/data/tdwg_level3.geojson`), in the Robinson projection, Antarctica left out, island parts under 1,000 km² dropped (each region keeps its largest part), simplified to 20 km. `scripts/maps/build-tdwg-outlines.R` builds them once into `apps/web/src/components/maps/tdwg-l3.json`: a `viewBox` and one SVG path per `LEVEL3_COD`, in kilometres. A map joins a region by that code, equal to RFC-78's `area_code_l3`.
- **R3** A region's value: `completeness` = `100 × species_with_data / wcvp_tree_species` (null when `wcvp_tree_species` is 0, RFC-78 R9); `mean`, `median`, `sd`, `cv`, `min`, `max` = that column of `region_continuous` (RFC-78 R10); `prevalence` = `100 × n_species_with_level / n_species_with_trait` (RFC-78 R11). Except for `completeness`, a region whose value rests on fewer than 3 species (`n_species`, `n_species_with_trait`) has no value. A region with no row, or with no value, is drawn as no data.
- **R4** Colours. Each kind has a ramp: `completeness` and `prevalence` magma, `mean` and `median` mako, `sd` and `cv` viridis, `min` and `max` cividis — the six-colour viridisLite ramp of that name, reversed so dark is high: magma `#FCFDBF #FE9F6D #DE4968 #8C2981 #3B0F70 #000004`, mako `#DEF5E5 #60CEAC #3497A9 #395D9C #382A54 #0B0405`, viridis `#FDE725 #7AD151 #22A884 #2A788E #414487 #440154`, cividis `#FFEA46 #CBBA69 #958F78 #666970 #31446B #00204D`. The scale runs from 0 to 100 for `completeness` and `prevalence`, and otherwise from the lowest to the highest value of the map. It is log10 when the kind is not a percentage, the map has at least two values, every value is positive and the highest is at least 100 times the lowest. A value is clamped to the scale, placed on it (the middle when both ends are equal) and coloured by interpolating between the six colours in CIELAB, as `scales::gradient_n_pal` does, written as `#RRGGBB`. No data is `#EBEBEB` and borders are `#8C8C8C`.
- **R5** `GET /api/maps` (`dataset.read`, resolves the viewer's `Visibility`) answers `{ data: [{ traitId, kind, levelId, regions, computedAt }] }`: one entry per map with at least one region with a value (R3), `levelId` null except for `prevalence`, `regions` the number of regions with a value, `computedAt` the snapshot's time. An entry appears only when its trait is visible to the viewer (RFC-33: inactive only with `dataset.read_inactive`), its kind fits the trait's value type, and, for `prevalence`, its state is visible. The plot restriction does not filter maps. Entries come by trait key, then kind in R1's order, then state in dictionary order; with no snapshot, the list is empty.
- **R6** `GET /api/maps/values?traitId=&kind=&levelId=` (`dataset.read`, resolves `Visibility`) answers `{ data: { regions: [{ code, name, value, nSpecies, fill }], legend: { stops, limits, log, percent, label, unit }, computedAt } }` for a map R5 would list to this viewer, and 404 `MAP_NOT_FOUND` otherwise; `levelId` is required for `prevalence` and refused for every other kind (400 `VALIDATION_FAILED`). `regions` holds every region with a row in the snapshot, `value` null where R3 gives none, `nSpecies` the species behind it, `name` the region's WCVP name and `fill` its colour (R4). `legend.stops` are the ramp's six colours, `limits` the scale's ends, and `label` reads `% of species with data`, `mean of species medians`, `median of species medians`, `sd of species medians`, `cv of species medians (%)`, `lowest species median`, `highest species median` or `% of species with the state`; `unit` is the trait's unit for the non-percentage kinds except `cv`, else null.
- **R7** Web: a **Maps** sidebar entry in the Data section, right after Traits (`dataset.read`, `map` icon). `/app/maps` shows one dictionary category at a time: a bar of the categories that have maps, in dictionary order, works as tabs (`?category=<key>`, default the first); below it a panel of buttons, one per trait of that category with maps (`?trait=<key>`, default the first; a trait given alone selects its category; an unknown or mapless key falls back to the default). The selected trait's name heads its maps, with its Categorical / Quantitative badge and a **Trait details** link. In this order, each under its own heading: **Data completeness** ("Share of tree species with data for this trait in each TDWG level-3 region."); for a quantitative trait **Summary statistics** — Mean, Median, SD, CV, Min and Max, each with a one-line explanation over the region's species medians; for a categorical trait **Prevalence by level**, one map per state in dictionary order ("Share of the region's tree species with data for this trait that hold each level; a species with several levels counts under each."). Each map is drawn as an SVG from R2's outlines and R6's fills, with a legend (the gradient, its two ends, the unit, and "log scale" when it is one); hovering or focusing a region names it, with its value and species count; its caption reads `TDWG level 3 regions · snapshot <date>`. A map opens full size in a dialog. Keyboard: the arrow keys move between the category tabs (Left/Right, Home/End) and between the trait buttons (Left/Right, Up/Down), and inside the dialog Left/Right show the previous/next map of the trait in page order, Escape closing it. With no maps the page reads "No maps yet."
- **R8** Trait-dictionary links: the trait page `/app/traits/$id` gains a **Maps** section after the distribution — the completeness map as a thumbnail and **See all maps for this trait →** — only when the trait has maps; the traits list shows a map link next to every trait with maps; on the species page, a trait card's help popover gains a **Maps** link when the trait has maps, and a trait with maps but no description still gets the popover for it. Every one of these links opens `/app/maps?trait=<key>`. Which traits have maps comes from R4; the web never builds a file name.
