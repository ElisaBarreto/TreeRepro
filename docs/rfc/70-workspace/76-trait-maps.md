# RFC-76 — Trait maps

| Field | Value |
|---|---|
| Status | accepted |
| Category | workspace |
| Supersedes | — |

## Context

The project produces global maps outside the platform: for every trait, the share of species in each region with data for it (completeness); for a categorical trait, the prevalence of each level; for a quantitative trait, the mean, minimum, maximum and standard deviation. The platform does not compute them. It organises and displays image files listed in a manifest (issue #197). The maps are private research output, so they are never committed to this public repository: they live in a directory on the server, mounted read-only into the API container, and publishing them is copying files there and running a check (issue #210).

The maps are global aggregates, not a species' trait records, so a plot-restricted viewer sees them too (RFC-33's plot restriction is about trait records). They still sit behind login, which is why the API serves them rather than the static web root.

## Rules

- **R1** Maps are image files in the maps directory — `MAPS_DIR` (env), default `apps/api/maps` (development and tests) — listed by its `manifest.csv` with the header `trait_key,map_kind,level_key,file,data_version`. `map_kind` is one of `completeness`, `prevalence`, `mean`, `min`, `max`, `sd`. `level_key` is required for `prevalence` and empty for every other kind. `file` matches `^[a-z0-9][a-z0-9._-]*\.(svg|webp)$` and names a file present in the directory; no two rows name the same file. `data_version` is the date the map was generated, a real calendar date `YYYY-MM-DD`. No two rows share `(trait_key, map_kind, level_key)`. A manifest breaking any of these is rejected as a whole, naming the line. A missing directory or a missing `manifest.csv` means no maps, never an error. Map images are never committed: `.gitignore` excludes `apps/api/maps/*.svg` and `*.webp`, and the API image carries none.
- **R2** Before publishing, `check:maps --dir <dir>` checks a maps directory against R1 and against the trait dictionary in the database: every `trait_key` is a dictionary trait; `prevalence` rows belong to categorical traits and their `level_key` is one of that trait's levels (case-insensitive); `mean`, `min`, `max`, `sd` rows belong to quantitative traits; `completeness` fits any trait. It prints one line per problem and the count of maps that would be shown, and exits 1 when any row breaks R1 or R2 (0 otherwise). It writes nothing.
- **R3** Every map uses TDWG level 3 botanical countries (WGSRPD) as its regions and carries its legend inside the image; the platform draws no legend of its own. Prevalence maps of one trait share one colour scale, so its levels compare honestly — a property of the delivered images, not something the platform checks.
- **R4** `GET /api/maps` (`dataset.read`, resolves the viewer's `Visibility`) answers `{ data: MapEntry[] }`, `MapEntry` being `{ traitId, kind, levelId, file, dataVersion }` (`levelId` null except for `prevalence`). A manifest row is included only when its trait exists and is visible to the viewer (RFC-33: inactive only with `dataset.read_inactive`), its kind fits the trait's value type as in R2, and, for `prevalence`, its level exists on that trait and is visible. The plot restriction does not filter maps. Rows come in manifest order.
- **R5** `GET /api/maps/files/:name` (`dataset.read`, resolves `Visibility`) serves the bytes of the file named by an entry R4 would give this viewer, and answers 404 `MAP_NOT_FOUND` for any other name, so a name is never used as a path unless the manifest lists it. `Content-Type` is `image/svg+xml` for `.svg` and `image/webp` for `.webp`; `Cache-Control: private, no-cache`; the response carries an `ETag` and answers 304 to a matching `If-None-Match`, so a replaced file reaches the browser at the next view.
- **R6** Web: a **Maps** sidebar entry in the Data section, right after Traits (`dataset.read`, `map` icon). `/app/maps` shows one dictionary category at a time: a bar of the categories that have maps, in dictionary order, works as tabs (`?category=<key>`, default the first). Below it, the category's heading and a panel of buttons, one per trait of that category with maps, in dictionary order (`?trait=<key>`, default the first; a trait given alone selects its category; an unknown or mapless key falls back to the default). The selected trait's name heads the maps, with its Categorical / Quantitative badge and a **Trait details** link (`/app/traits/$id`). Names, levels and categories come from the dictionary, never from the manifest. With no maps at all the page reads "No maps yet."
- **R7** For the selected trait, in this order, each under its own heading: **Data completeness**, with the legend "Share of tree species with data for this trait in each TDWG level-3 region."; then, for a quantitative trait, **Summary statistics** with Mean, Min, Max and SD in that order (missing kinds left out), each headed by its name and a one-line explanation (Mean: mean of the species means in the region; Min: lowest species mean; Max: highest species mean; SD: standard deviation of the species means); for a categorical trait, **Prevalence by level**, one map per level in dictionary level order, each headed by the level name, under the legend "Share of the region's tree species with data for this trait that hold each level; a species with several levels counts under each." A missing completeness map leaves its section out. Each map's caption reads `TDWG level 3 regions · <data_version>`; a map opens full size in a `<dialog>`; images load lazily inside a fixed-ratio frame with an alt text naming kind, trait and level. The breadcrumb reads `Data › Maps`.
- **R8** Trait-dictionary links: the trait page `/app/traits/$id` gains a **Maps** section after the distribution — the completeness map as a thumbnail and **See all maps for this trait →** — only when the trait has maps; the traits list shows a map link next to every trait with maps; on the species page, a trait card's help popover gains a **Maps** link when the trait has maps, and a trait with maps but no description still gets the popover for it. Every one of these links opens `/app/maps?trait=<key>`. Which traits have maps comes from R4; the web never builds a file name.
