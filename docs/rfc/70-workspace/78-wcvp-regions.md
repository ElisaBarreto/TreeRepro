# RFC-78 — WCVP regions

| Field | Value |
|---|---|
| Status | accepted |
| Category | workspace |
| Supersedes | — |

## Context

The maps (RFC-76) show, for each WCVP / TDWG level-3 region, how many of the species native there have data for a trait. They need the World Checklist of Vascular Plants (WCVP, Kew): its accepted species, each species' native regions, and every accepted species of a region for the completeness denominator. The platform loads the two files Kew distributes, `wcvp_names.csv` and `wcvp_distribution.csv`, and keeps only what the owner's `wcvp_region_index()` keeps (`platform_package/R/region_summary_tables.R`; epic #286, issue #291). The weekly snapshot (#292) reads these tables.

## Rules

- **R1** Tables. `wcvp_species` holds one row per WCVP accepted species: `plant_name_id`, `taxon_name`, `is_tree` and `file_order` (its line in `wcvp_names.csv`). `wcvp_regions` holds one row per level-3 region (botanical country): `area_code_l3`, its `name`, and the level-2 region and level-1 continent it belongs to, `region_code_l2`, `region`, `continent_code_l1` and `continent` (R5). `wcvp_distribution` holds one row per accepted species × region where the species occurs, native or introduced, with `introduced` true for an introduced occurrence (R4). They hold the last load only. The app role reads them; only the import (R2) writes them.
- **R2** Import. `pnpm --filter @treerepro/api import:wcvp --names <wcvp_names.csv> --distribution <wcvp_distribution.csv>` reads Kew's files: pipe-separated (`|`), UTF-8, LF or CRLF line endings, a header line, no quoting (a `"` is an ordinary character). It reads both headers first and refuses, before any write, a file missing a column it needs, naming the file and the columns: `plant_name_id`, `taxon_rank`, `taxon_status`, `taxon_name` and `lifeform_description` in the names file; `plant_name_id`, `continent_code_l1`, `continent`, `region_code_l2`, `region`, `area_code_l3`, `area`, `introduced`, `extinct` and `location_doubtful` in the distribution file. Other columns are ignored. One transaction replaces the previous load wholesale, so a failure leaves the previous load in place. It prints the counts of accepted species, tree species, regions and distribution rows kept. A run is not recorded in `import_batches` (RFC-68 R1): it replaces reference data rather than adding records, and has no rows to accept or reject one by one.
- **R3** Accepted species. A names row is kept when its `taxon_status` is `Accepted`, its `taxon_rank` is `Species`, and neither its `plant_name_id` nor its `taxon_name` is blank. `taxon_name` is stored trimmed, with each run of whitespace collapsed to one space. `is_tree` is true when `lifeform_description` contains, ignoring case, the whole word `tree` (`shrub or tree` is a tree, `treelet` is not), or `arborescent`, or `phanerophyte`; a blank `lifeform_description` is not a tree. The flag serves only the trees completeness denominator.
- **R4** Distribution. A distribution row is kept when its `area_code_l3` is not blank, its `plant_name_id` is a kept accepted species (R3), and neither `extinct` nor `location_doubtful` is `1`: extant and non-doubtful occurrences, native or introduced. The code is upper-cased first (WCVP v15 has a few lower-case codes, such as `nep` for Nepal). A species × region pair is stored once; it is `introduced` only when every kept row of the pair has `introduced` = `1`, so a species both native and introduced in a region is native there.
- **R5** Regions. Every upper-cased, non-blank `area_code_l3` of the distribution file is a region, whether or not a kept row uses it. Its name is the first non-blank `area` given for the code in file order, or the code itself if none is. Its `region_code_l2`, `region`, `continent_code_l1` and `continent` are each the first non-blank value given for the code in file order, trimmed, or null if none is; a name is the code itself when only the code is given.
- **R6** Matching. A platform species matches the WCVP accepted species whose `taxon_name` equals the species' `canonical_name`, both trimmed with whitespace collapsed (R3). A name shared by two accepted species matches the first in WCVP file order (`file_order`). A species with no match (a GBIF-only or Unplaced name) has no region and appears in no map; its species summary (RFC-77) is unaffected. The view `wcvp_species_match (species_id, plant_name_id)` answers this rule, one row per matched species.
- **R7** Region tables. The weekly snapshot (R12) writes three tables, each replaced whole: `region_completeness(platform, trait_id, area_code_l3, species_with_data, wcvp_species, wcvp_tree_species)`, `region_continuous(platform, trait_id, area_code_l3, n_species, mean, sd, median, min, max, cv)` and `region_categorical(platform, trait_id, level_id, area_code_l3, n_species_with_level, n_species_with_trait)` (`trait_id` references `traits` and `level_id` references `trait_levels`, both cascading on delete, so the dictionary sync of RFC-62 R9 never trips on them; `area_code_l3` is a plain code, not a reference, because `import:wcvp` truncates `wcvp_regions` (R2)), and `region_snapshot(platform, computed_at)`, one row per platform. `platform` is `treerepro` or `plantrepro` (RFC-14 R1), part of each table's primary key, and has no default: every row states the platform whose scope (R8) it was computed over. The app role reads and writes them.
- **R8** Inputs, per platform. For each platform, the species summaries of RFC-77 over the records every signed-in viewer of that platform reads: live, harmonised, of an active species in the platform's scope (RFC-33 R2: on TreeRepro reviewed trees only, on PlantRepro every species), an active trait and an active (or no) level (RFC-33 R2 for a viewer without `dataset.read_inactive` and without `records.review`, and no plot restriction, since maps are global aggregates, RFC-76). A species' regions are those where its WCVP match (R6) is native in `wcvp_distribution` (`introduced` false); an unmatched species has none. Introduced occurrences never reach the region tables.
- **R9** Completeness, one row per trait × region with at least one species with data: `species_with_data` = the distinct species of the region with a species median (continuous, RFC-77 R5) or a state (categorical, RFC-77 R6) for the trait; `wcvp_species` and `wcvp_tree_species` = the distinct WCVP accepted species, and accepted tree species, native to the region (R4, `introduced` false). Both denominators are stored on every row of both platforms; each platform reads its own (RFC-76 R3): TreeRepro the trees completeness, `100 × species_with_data / wcvp_tree_species` (null when `wcvp_tree_species` is 0), and PlantRepro the all-species completeness, `100 × species_with_data / wcvp_species` (null when `wcvp_species` is 0).
- **R10** Continuous, one row per quantitative trait × region over the species medians of the region: `n_species`; `mean`; `sd`, the sample standard deviation (null under two species); `median` (the middle value, or the mean of the two middle ones); `min`; `max`; `cv` = `100 × sd / mean`, only when `mean` is positive and `sd` is set.
- **R11** Categorical, one row per categorical trait × state × region: `n_species_with_level`, the distinct species of the region holding the state, and `n_species_with_trait`, the distinct species of the region with any state of the trait. A species with several states counts under each, so a trait's percentages (`100 × n_species_with_level / n_species_with_trait`) can add up to more than 100.
- **R12** Snapshot. `pnpm --filter @treerepro/api build:snapshot` computes R9–R11 for both platforms and replaces the tables of R7 and `region_snapshot` in one transaction, so a reader never sees half a snapshot and a failure leaves the previous one; earlier snapshots are not kept. The API process also runs it from a timer that ticks hourly, the first tick one minute after start-up, and runs when no `completed` snapshot finished in the last 7 days. One run at a time: a run takes the session advisory lock `4665` and, finding it held, records itself `skipped`. Every run, from the command or the timer, is recorded in `job_runs` with `kind = 'snapshot'` (RFC-74 R1): `completed` with its counts per platform in `detail` (`{ treerepro: { completeness, continuous, categorical }, plantrepro: { … } }`), `skipped`, or `failed` with a failure code; the command exits 0 when the run completed or was skipped and 1 when it failed.
