# RFC-60 — Taxonomy catalog

| Field | Value |
|---|---|
| Status | accepted |
| Category | dataset |
| Supersedes | — |

## Context

Every trait record (RFC-63) belongs to a species. Species names in the compiled dataset are standardized to the World Checklist of Vascular Plants (WCVP), with the GBIF name as an alternative; some rows arrive without a WCVP name, a genus or a family. The catalog keeps one row per species, its alternative names, and the genus and family it belongs to, so filters and searches never depend on free text.

## Rules

- **R1** Tables (ids `uuid` default `uuidv7()`, `created_at timestamptz` default `now()`, `created_by uuid` referencing `users` and null for rows created by the import):
  - `families(id, name text unique, order_name text null, created_at, created_by)`. `order_name` is normalised per R2 like every other name; it is filled by the import, from the GBIF backbone's order, for a family whose value is still null (RFC-64 R5).
  - `genera(id, family_id uuid null references families restrict, name text unique, created_at, created_by)`
  - `species(id, genus_id uuid null references genera restrict, canonical_name text unique, name_source text in ('wcvp', 'gbif', 'original'), active boolean not null default true, trait_count integer not null default 0, tree_flag text null check in ('bgci_and_wcvp_tree', 'bgci_and_wcvp_mixed_form', 'bgci_wcvp_not_tree', 'bgci_no_wcvp_lifeform', 'wcvp_tree', 'wcvp_mixed_form', 'growth_form_unanimous', 'growth_form_majority'), plant_type text not null check in ('tree', 'not_tree'), plant_type_status text not null check in ('proposed', 'reviewed'), created_at, created_by)`. `plant_type` is the species' *plant type* (`PLANT_TYPES` in `packages/contracts/src/platform.ts`, labelled `Tree` and `Not a tree`; the list may grow, which widens the check) and `plant_type_status` says whether a holder of `records.review` has reviewed it (`PLANT_TYPE_STATUSES`). Neither column has a default, so every insert states both: the import (RFC-64 R5), a direct creation (R9, RFC-65 R18) and an approved proposal (RFC-75 R4). Migration `0058_species_plant_type` backfills every existing species to `tree` / `reviewed` and indexes `(plant_type, plant_type_status)`. The tree basis below stays the evidence for why a species counts as a tree; the plant type is what a platform's scope reads (RFC-14 R9). `tree_flag` is the *tree basis*: the evidence on which the owner's release counts the species as a tree (BGCI GlobalTreeSearch, WCVP lifeform, or the other sources' growth form), set by the import from the file's `tree_flag` (RFC-64 R5); null for a species the file gives none. Each flag has a meaning, the owner's (2026-11-05), shown wherever the flag is: `bgci_and_wcvp_tree` BGCI + WCVP says “tree”; `bgci_and_wcvp_mixed_form` BGCI + WCVP says e.g. “shrub or tree”; `bgci_wcvp_not_tree` BGCI says tree, WCVP says e.g. “shrub”; `bgci_no_wcvp_lifeform` BGCI says tree, WCVP has no lifeform; `wcvp_tree` WCVP “tree”, not in BGCI; `wcvp_mixed_form` WCVP mixed form, not in BGCI; `growth_form_unanimous` Fallback, every source says tree; `growth_form_majority` Fallback, most sources say tree.
  - `species_names(id, species_id uuid references species restrict, name text, name_type text not null default 'gbif' check in ('gbif', 'synonym', 'common'), language char(2) null, source text not null default 'gbif', gbif_usage_key text null, created_at; unique (species_id, name); check (language is null or name_type = 'common'); check (gbif_usage_key is null or name_type = 'gbif'))`. `source` was constrained to `'gbif'` and becomes free text 1–200 characters naming the provider (`gbif`, `WCVP`, `Flora e Funga do Brasil`, a DOI…). Migration (`species_names`): drop the old check on `source`, add the `name_type` and `language` columns and the two new checks; existing rows keep `name_type = 'gbif'`, `source = 'gbif'`. `gbif_usage_key` is 1–64 characters when present. Only a common name carries a `language`; an imported one may have none (RFC-68 R12), while the write route of R9 still asks for one. The function `search_key(text)` (immutable) is `lower(unaccent(x))` with every character that is not a letter or a digit removed: `Pau-Brasil`, `pau brasil` and `paubrasil` share the key `paubrasil`, `Ipê` and `ipe` the key `ipe`, `Citrus × aurantium` and `Citrus aurantium` the key `citrusaurantium`.
- **R2** Names are stored trimmed with internal whitespace collapsed to one space; case is preserved. Lookups during import compare the normalised strings exactly.
- **R3** The canonical name of a species is its WCVP name (`name_source = 'wcvp'`). When no WCVP name is known the GBIF name is used (`gbif`), and failing that the name given by the original source (`original`). A species whose `name_source` is not `wcvp` is an *unresolved taxon*; a species without a genus or a genus without a family is *unresolved taxonomy*. Both are reported by the API and never block an import.
- **R4** Alternative names are GBIF names (import, keeping the GBIF usage key), synonyms and common names (import or `taxa.manage`). A name is never stored twice for a species, whatever its type; a name equal to the canonical name is refused (409 `SPECIES_NAME_TAKEN`, as today). Species search (R6) matches canonical and alternative names of every type.
- **R5** A family, genus or species referenced by any other row cannot be deleted (foreign keys `restrict`). No route deletes or merges taxa; renames and reassignments are the writes of R9.
- **R6** `GET /api/species?q=&familyId=&genusId=&unresolved=&unknownLevels=&contested=&outliers=&status=&scope=&plotId=&categoryKey=&traitId=&traitData=&treeFlag=&plantType=&continent=&region=&area=&introduced=&sort=&order=&cursor=&limit=` (`dataset.read`; visibility RFC-33 R3). `q` is 2–100 characters. Tier 1 keeps the species whose canonical name equals `q` case-insensitively (`canonical_name ilike <q with %, _ and \ escaped>` — no wildcard, served by the trigram index); if none match, tier 2 keeps the species where `search_key(q)` (R1) is a substring of `search_key` of the canonical name or of any alternative name, of any type — case, accents, spaces, hyphens and other punctuation ignored (`pg_trgm` indexes on both keys). The non-empty tier is answered, ordered as today; the cursor encodes the tier so a page never mixes tiers. Without `q` nothing changes. `unresolved=true` keeps only unresolved taxa and unresolved taxonomy, and `unknownLevels=true` keeps only species with a visible record whose `harmonisation` is `unknown_level`. Both are reviewer filters: they apply for a holder of `records.review` and are ignored for any other viewer, like `status` below. `contested=true`, open to every viewer, keeps only species with a contested species × trait (RFC-63 R14). `outliers=true`, open to every viewer as well, keeps only species with a visible record (RFC-33 R2) on a visible trait whose `outlier_flag` is not null (RFC-63 R1); a flag on data the viewer cannot see never counts. `traitId` (uuid of a visible trait; unknown or invisible → 404 `TRAIT_NOT_FOUND`) with `traitData=with` (default) keeps species that have a coverage row (RFC-69 R1) for the trait; `traitData=missing` keeps species with none. `categoryKey` (existing category; unknown → 400, path `categoryKey`) without `traitId`: `with` keeps species with a coverage row for any visible trait of the category; `missing` keeps species with none. With `traitId`, `categoryKey` must be the trait's category (400 otherwise). `sort=name` (default) is the current order — `canonical_name` ascending, then `id`, with the same composite keyset cursor (RFC-11 R6); `sort=completeness` orders by `trait_count` ascending, then `canonical_name` ascending, then `id` ascending, with the composite cursor `[trait_count, canonical_name, id]`. `sort` may also be `family` (the family name, a species with none first ascending), `genus`, `plantType` (the stored `plant_type`, so `not_tree` before `tree` ascending), `treeBasis` (the meaning of the tree flag, R1, a species with none first ascending), `traits` (`trait_count`) or `records` (the species' record count on `traitId`, which it requires — 400 `VALIDATION_FAILED` with path `sort` otherwise), each in `order` (`asc` by default) and then by canonical name and id in the same direction (RFC-11 R10); `order=desc` applies to `name` too, never to `completeness`. On the species search the table's Species, Family, Genus, Traits, (with a trait filter) Records, Plant type and Tree basis headers set `sort` and `order`. Item: `{ id, canonicalName, nameSource, active, genus: { id, name } | null, family: { id, name } | null, matchedName, matchedNameType, unresolvedTaxon, traitCount, traitRecordCount, treeFlag, plantType, plantTypeStatus }`, where `matchedName` is the alternative name that matched when the canonical name did not, else `null`, `matchedNameType` is `'gbif' | 'synonym' | 'common' | null`, the type of the name that matched, `unresolvedTaxon` is the R3 flag (either kind) for a viewer holding `records.review` and `null` for any other viewer (RFC-33 R2: reviewer-only data), `traitCount` is `species.trait_count` (visibility-blind by design, so it can disagree with the `traitId` / `categoryKey` filters above for a viewer who cannot see every trait — RFC-69 R1), and `traitRecordCount` is `null` unless `traitId` is given, in which case it is the coverage `record_count`, `0` in missing mode. `status` is `active`, `inactive` or `all` (default `all`); a restricted viewer (RFC-33 R1) gets `active` whatever the parameter says — the parameter is ignored, not refused, so a shared link works for everyone. `scope` (`plots` or `all`) and `plotId` filter by plot membership per RFC-33 R6. `treeFlag`, open to every viewer, is a comma-separated list of 1–8 distinct tree flags (R1; anything else answers 400 `VALIDATION_FAILED` with path `treeFlag`) and keeps the species whose `tree_flag` is any of them; without it every species is kept, null flag included. The item gains `treeFlag`, the species' `tree_flag` (null when unset), and so does the detail of R7; the species search shows it as a Tree basis column, after Match, and offers the filter as one checkbox per flag, none checked by default, in a list that closes on a click outside it or on Escape. `plantType`, open to every viewer, is one plant type (R1; anything else answers 400 `VALIDATION_FAILED` with path `plantType`) and keeps the species of that type, whatever their status; without it every type is kept. The item and the detail of R7 gain `plantType` and `plantTypeStatus`; the species search shows them as a Plant type column, after Traits and, while a trait filter is set, Records (`Tree`, or `Not a tree`, followed by `(proposed)` while the status is `proposed`), and offers the filter as a Plant type select in the Scope group (All / Tree / Not a tree). `continent` (WCVP level-1 codes, 1–2 digits each), `region` (level-2 codes, 1–3 digits each) and `area` (level-3 botanical country codes, 3 letters each, upper-cased before use), open to every viewer, are each a comma-separated list of 1–100 distinct codes (anything else answers 400 `VALIDATION_FAILED` with its path; an unknown code matches nothing). The chosen places are, most specific first in each branch of WCVP's hierarchy (RFC-78 R1): every chosen botanical country; every chosen region none of whose botanical countries is chosen; every chosen continent none of whose regions or botanical countries is chosen. The filter keeps the species whose WCVP match (RFC-78 R6) occurs in any level-3 region of `wcvp_regions` lying in a chosen place, so `continent=8&region=84` is Brazil and `continent=4&area=BZN` is Asia-Tropical and Brazil North. Only native occurrences count, unless `introduced=true`, which counts introduced ones too; `introduced` without a geographic code changes nothing. A species with no WCVP match is kept by no geographic filter. The species search offers them as a **Geography** group, after Traits, fed by R14: Continent, Region and Botanical country, each a closed control that opens onto one checkbox per place (as Tree basis does: arrow keys move between the boxes, a click outside or Escape closes it), none checked by default. Region lists the regions of the chosen continents, else every region; Botanical country lists the level-3 regions of the chosen continents, else every one, narrowed in each continent to its chosen regions when it has any; each is grouped under its continent. After any change, a chosen region or botanical country its list no longer shows is dropped, so unchecking a continent drops the regions and botanical countries it held. An **Include introduced occurrences** checkbox follows, unchecked by default and disabled while no place is chosen.
- **R7** `GET /api/species/:id` (`dataset.read`) returns the item (R6), whose `family` gains `order` (the family's `order_name`, null when unset), plus `names: [{ name, nameType, language, source, gbifUsageKey }]`, `plots: [{ id, code, name }]` (the plots the species belongs to among the viewer's assigned plots, `plots.manage` included, RFC-67 R8), `recordCount` and `traitCount` (distinct traits with at least one record); unknown id answers 404 `SPECIES_NOT_FOUND`. An invisible species (RFC-33 R2) answers 404 `SPECIES_NOT_FOUND`. `traitCount` here is R6's field, not a second count: it is visibility-blind by design (RFC-69 R1), so like R6's it includes traits a curator has deactivated, and neither it nor `recordCount` is filtered by trait visibility — RFC-33 R3 omits invisible rows from lists and leaves counters unaffected. The trait list of RFC-63 R10 (`GET /api/species/:id/traits`) on the same page *is* filtered (RFC-33 R3), so the two can disagree for a viewer who cannot see every trait.
- **R8** `GET /api/families?cursor=&limit=` and `GET /api/genera?familyId=&q=&sort=name|family&order=&cursor=&limit=` (`dataset.read`) list `{ id, name }` (genera add `family`) ordered by name then id with a composite cursor — genera also by family name, a genus with none first ascending (RFC-11 R10); `q` on genera is a case-insensitive prefix match of 1–100 characters.
- **R9** Writes require `taxa.manage`; bodies are strict JSON; names are 1–200 characters normalised per R2; nothing is deleted. `POST /api/families` `{ name }` and `PATCH /api/families/:id` `{ name }` answer `{ id, name }` (409 `FAMILY_NAME_TAKEN`; 404 `FAMILY_NOT_FOUND`). `POST /api/genera` `{ name, familyId? }` and `PATCH /api/genera/:id` `{ name?, familyId? }` — `familyId: null` detaches the genus — answer the genus item of R8 (409 `GENUS_NAME_TAKEN`; 404 `GENUS_NOT_FOUND`, `FAMILY_NOT_FOUND`). `POST /api/species` `{ canonicalName, nameSource, genusId?, plantType? }` (the plant type and its status per RFC-65 R18) and `PATCH /api/species/:id` `{ canonicalName?, nameSource?, genusId?, active? }` — `genusId: null` detaches — answer the species detail of R7 (409 `SPECIES_NAME_TAKEN`; 404 `SPECIES_NOT_FOUND`, `GENUS_NOT_FOUND`); audit `fields` may contain `active`. `POST /api/species/:id/names` `{ name, nameType, language?, source?, gbifUsageKey? }` — `source` defaults to `'manual'`; validation per R1's checks (`gbifUsageKey` 1–64 characters when present; 400 `VALIDATION_FAILED` with the failing path) — adds an alternative name and answers the species detail; 409 `SPECIES_NAME_TAKEN` when the name equals the species' canonical name or one of its alternative names. Creates answer 201, updates 200. A `PATCH` whose fields all equal the stored values changes nothing and records nothing; a `PATCH` with no field answers 400 `VALIDATION_FAILED`.
- **R10** Every write of R9 records an audit entry in its transaction (RFC-41 R5): `taxa.created` or `taxa.updated`; `target_type` is the table (`families`, `genera`, `species`, `species_names`), `target_id` the row id; `metadata.kind` is `family`, `genus`, `species` or `species_name`; `metadata.fields` lists the changed fields on an update; `metadata.speciesId` accompanies a name. Names never enter the metadata.
- **R11** `GET /api/species/tree-flags` (`dataset.read`; visibility RFC-33 R3) answers `{ data: [{ treeFlag, speciesCount }] }`: one entry per tree flag, in R1's order, `speciesCount` being the number of species visible to the viewer (RFC-33 R2) whose `tree_flag` is that flag, 0 when none, among the species R12's filters keep — every one of them but `treeFlag`, which it refuses (400 `VALIDATION_FAILED`), as it does R6's `sort`, `order`, `cursor` and `limit`. Without a filter it counts every visible species. Leaving `treeFlag` out makes each count what its box would add: ticking one never drops the others to 0. Its refusals are R6's. The species search's Tree basis filter (R6) shows each meaning followed by its count, `(n = 34,941)`.
- **R12** `GET /api/species/count` (`dataset.read`; visibility RFC-33 R3) takes R6's filters — `q`, `familyId`, `genusId`, `unresolved`, `unknownLevels`, `contested`, `outliers`, `status`, `scope`, `plotId`, `categoryKey`, `traitId`, `traitData`, `treeFlag`, `plantType`, `continent`, `region`, `area`, `introduced` — and none of its `sort`, `order`, `cursor` or `limit` (any of them, or an unknown parameter, answers 400 `VALIDATION_FAILED`), and answers `{ data: { count } }`: the number of species R6 pages through for the same filters and viewer, `q`'s tier included (the exact canonical match when there is one, else the substring matches). Its refusals are R6's (an unknown or invisible trait 404 `TRAIT_NOT_FOUND`, a category mismatch 400, a plot outside a restricted viewer's 403…). The species search shows the count above its table, `1,234 species` (`1 species` for one), following the filters.
- **R13** A name held by a hidden species (RFC-33 R2). On a platform whose scope hides a species — on TreeRepro, a `not_tree` or `proposed` one — that species' canonical and alternative names (compared ignoring case) cannot be registered again: `POST /api/species`, `POST /api/species/:id/names`, `POST /api/species/proposals` and its approval (RFC-75 R2, R4) answer 409 `SPECIES_NAME_TAKEN` with the message “This species already exists, but it is not classified as a tree on TreeRepro. A manager can review its type.” and no `details`: no id, no link. The refusal fires only when the name's holder is in the catalog and hidden by the platform's scope alone; a species hidden for another reason (inactive, outside the viewer's plots) keeps the answer it had. On PlantRepro, whose scope hides nothing, it never fires.
- **R14** `GET /api/species/regions` (`dataset.read`) answers `{ data: [{ code, name, regionCode, region, continentCode, continent }] }`: every level-3 region of `wcvp_regions` (RFC-78 R1, R5), `code` being `area_code_l3`, ordered by `continent_code_l1`, then `region_code_l2` (both numerically, a null last), then `name`. It is reference geography, not dataset data, so it is the same for every viewer and platform (exempt from RFC-33 R10). A literal segment, registered before `/:id`.

## Data model

See R1. Indexes: unique on `families.name`, `genera.name`, `species.canonical_name`; `genera(family_id)`, `species(genus_id)`, `species(trait_count, canonical_name, id)` (the completeness order of R6); GIN trigram on `species.canonical_name`, `species_names.name`, `search_key(species.canonical_name)` and `search_key(species_names.name)`.

## Open questions

Merging two species rows (synonyms discovered later) and WCVP/GBIF lookups when a scientist creates a species are deferred to a later RFC.
