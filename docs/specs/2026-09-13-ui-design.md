## 1. Context

Plans 01–04 delivered the API: authentication, RBAC, administration, retention. The web app has one screen, the landing page, which is the sign-in form (visual identity spec). A signed-in visitor sees "Signed in as …" and nothing else. This plan gives every API capability a screen and fixes the two frontend issues left by plan 01: components need a real RFC to cite (#11) and the production CSP forbids inline styles (#9).

Decisions that override or refine earlier specs:

- `/` stays the sign-in screen (visual identity) and the only public page with motion. The workspace lives under `/app`; the foundation's `/login` and `/` dashboard are dropped.
- Forms use local React state and the contracts' Zod schemas for client-side feedback, as the landing form already does; `react-hook-form` is not adopted.
- Component tests mock the `apps/web/src/api/*` modules with `vi.mock` (the established pattern; `apiFetch` has its own fetch-level tests); `msw` is not adopted.
- Data export is gone (plan 04): settings has no "export my data".

Constraints inherited: the web app contains no business rules and calls the API only through `apiFetch` (RFC-10 R3); every response shape comes from `packages/contracts`; English copy; exact dependency versions; RFC first, then failing test, then code.

## 2. Decisions summary

| Topic | Decision |
|---|---|
| Routing | Public: `/`, `/invite/$token`, `/forgot-password`, `/reset-password/$token`. Authenticated, under the `/app` layout: `/app`, `/app/settings`, `/app/admin/users`, `/app/admin/users/$id`, `/app/admin/roles`, `/app/admin/audit`. TanStack Router, file-based, `routeTree.gen.ts` committed. |
| Session gate | The `/app` layout's `beforeLoad` ensures the `me` query (`GET /api/auth/me`); a failure redirects to `/`. `/` with a live session redirects to `/app`. An `AUTH_UNAUTHENTICATED` answer (a 401 with that code) from any later call inside `/app` navigates to `/` and then forgets the session state (a `QueryCache`/`MutationCache` `onError` hook, wired by `createAppQueryClient` in `lib/session.ts`). |
| Permission gate | `me.permissions` drives navigation and buttons (`hasPermission(me, key)`); `admin.access` shows the Admin section and guards the `/app/admin` layout, which renders "You do not have permission to open this area" without redirecting. A 403 from the API renders inline as the same sentence. UX only — the API re-checks (RFC-32). |
| Look | Workspace on a light ground (`mist-50`), dark sidebar (`canopy-900`), amber actions (`pollen-500`), Sora headings, Manrope body — the visual-identity tokens. No motion beyond hover/focus transitions. |
| UI kit | `apps/web/src/components/ui/`: `Button` (primary/secondary/danger, `pending`), `Input`, `Field` (label + error + hint), `Alert` (error/success/info), `Dialog` (native `<dialog>`), `Table`, `Badge`, `PageHeader`, `EmptyState`. Tailwind classes only; no inline `style`, no style-injecting library (#9). Navigation entries are a static list `NAV_ENTRIES` in `components/shell/nav.ts` that other plans append to (the dataset plan adds Species, Traits, References, Imports). |
| Errors | Each page maps API codes to one sentence through a local `errorMessage(error)` function, following `loginErrorMessage`; `VALIDATION_FAILED` details map to field errors by `path`. Unknown codes: "Something went wrong. Try again." |
| Forms | Local state; `schema.safeParse` from contracts before submit for instant feedback; the API answer is authoritative. |
| QR code | `qrcode` (npm, pinned) renders the `otpauthUri` into a `<canvas>` — no inline style, CSP-safe. |
| Audit action catalog | `AUDIT_ACTIONS` moves from `apps/api/src/audit/actions.ts` to `packages/contracts/src/audit.ts` (the API re-exports it and its RFC-41 table test keeps comparing); the audit page's action filter reads it (plan 05b). |
| E2E | Playwright against `compose.yml` + `compose.e2e.yml` (Mailpit, loopback ports, generated test secrets). One critical flow plus password reset plus CSP assertions (plan 05c). |

## 3. RFC-13 — Presentation layer (rules, plan 05a writes the RFC)

- R1 `apps/web` contains no business rules and reaches the API only through `apiFetch` (RFC-10 R3); every request and response type comes from `packages/contracts`.
- R2 Route map as in section 2. Every route under `/app` requires a session: the layout resolves `me` before rendering and redirects to `/` otherwise; `/` redirects a signed-in visitor to `/app`.
- R3 Navigation entries and action buttons render only when `me.permissions` holds the permission the target route or API call requires; `admin.access` gates the Admin section. This is presentation only: the API is the authority (RFC-32 R4).
- R4 An `AUTH_UNAUTHENTICATED` answer (a 401 with that code) inside `/app` clears the session state and returns to `/`; other 401 codes are form errors shown where the action was attempted; a 403 answer is shown inline as "You do not have permission to do this." No global toasts.
- R5 CSP: no `style` attributes in markup, no `<style>`/`<link>` injection by libraries, no third-party scripts, styles or fonts; Tailwind utility classes and the visual-identity tokens only (CSSOM property assignment is not blocked by the CSP but is avoided). Playwright asserts the served document contains no inline script or style and that no CSP violation is reported (plan 05c).
- R6 Forms hold local state, validate with the contracts' schemas for feedback, and map API error codes to English sentences per page; validation `details` map to fields by `path`.
- R7 Motion is confined to the landing page (visual identity); other screens use hover/focus transitions only, and respect `prefers-reduced-motion`.
- R8 Every page has component tests (Testing Library, `vi.mock` of `apps/web/src/api/*`): rendering by permission, the happy path, mapped errors, and — for `/app` routes — the 401 and 403 behaviour. Critical flows have Playwright end-to-end tests (RFC-01).
- R9 Copy is English; error messages never echo internals (RFC-02 R9); email/password errors on sign-in stay indistinguishable (RFC-22 R2).

### Behaviour

- **Invite** `/invite/$token`: password + confirm; `POST /auth/invite/accept { token, password }`; success → the session cookie is set → navigate to `/app`. `AUTH_TOKEN_INVALID` → "This invitation is no longer valid. Ask an administrator to send a new one." `AUTH_PASSWORD_WEAK` → the `details` messages under the password field.
- **Forgot** `/forgot-password`: email; `POST /auth/password/forgot`; always "If that email has an account, a reset link is on its way." (RFC-21 R5).
- **Reset** `/reset-password/$token`: password + confirm; `POST /auth/password/reset { token, newPassword }`; success → "Your password is changed." with a link to `/`; `AUTH_TOKEN_INVALID` → "This link is no longer valid. Request a new one."
- **Workspace** `/app`: heading "Workspace", the user's name, "Research data arrives in the next release."
- **Settings** `/app/settings`, four sections on one page:
  1. Profile — name (`PATCH /api/me`), email read-only; success alert "Name saved."
  2. Password — current, new, confirm (`POST /auth/password/change`); `AUTH_INVALID_CREDENTIALS` → "Your current password is incorrect."; `AUTH_PASSWORD_WEAK` → details.
  3. Two-factor — off: "Set up" → `POST /auth/totp/setup` → QR canvas + secret text + six-digit code → `POST /auth/totp/confirm` → ten recovery codes shown once with "I saved these codes" to dismiss; on: "Disable" → dialog with password and code or recovery code → `POST /auth/totp/disable`. `AUTH_TOTP_INVALID` → "That code is not valid."
  4. Sessions — table of `GET /me/sessions` (user agent, IP, last seen, "This device"); "Sign out" per row (`DELETE /me/sessions/:id`, absent on the current one); "Sign out everywhere" (`POST /auth/logout-all`, which also ends the current session and returns to `/`).
- **Shell**: sidebar with wordmark, Workspace, Settings, and — with `admin.access` — Admin: Users, Roles, Audit; header with the user's name and "Sign out" (`POST /auth/logout` → reset `me` → `/`).
- **Landing**: the "Signed in as …" branch becomes a redirect to `/app` (route `beforeLoad`).

### Testing (05a)

Component tests per page and section as RFC-13 R8; `lib/session.test.ts` for `hasPermission` and the 401 handler; `components/ui/*.test.tsx` for the kit's states (pending, error, dialog open/close). `routeTree.gen.ts` is regenerated by the Vite plugin and committed.

## 5. Plan 05b — administration pages

- `/app/admin` layout: requires `admin.access`, else the no-permission page. Sub-navigation Users / Roles / Audit.
- **Users** list: table (name, email, status badge, roles, created), status filter, "Load more" on `meta.nextCursor`; "Invite user" (`users.invite`) dialog → `POST /api/admin/users`; `MAIL_SEND_FAILED` → "The user was created but the invitation email failed. Use Resend invitation." then refresh; `USER_EMAIL_TAKEN` → field error.
- **User detail** `/app/admin/users/$id`: header (name, email, status, TOTP on/off, created); sections by permission: name (`users.update`), roles as checkboxes over `GET /api/admin/roles` (`users.update`, `PATCH` with the full id list; `ROLE_LAST_ADMIN` → "This is the last active administrator."), suspend/reactivate with confirm dialog (`users.suspend`), resend invitation (`users.invite`, only when `invited`), sessions (`sessions.read`, revoke one/all with `sessions.revoke`).
- **Roles**: list (name, description, permission count, "system" badge); create/edit dialog: name, description, permission checkboxes grouped by resource prefix from `GET /api/admin/permissions` (retired keys — description ending in "(retired)" — hidden); delete with confirm. Codes: `ROLE_NAME_TAKEN` (field), `ROLE_IS_SYSTEM`, `PERMISSION_UNKNOWN`.
- **Audit**: filters actor (user id, with a datalist of names from the loaded users list), action (select over `AUDIT_ACTIONS` from contracts), from/to (datetime-local); table (at, actor name or short id, action, target, ip, user agent truncated with full text in `title`, metadata as collapsed JSON); "Load more".
- API layer `apps/web/src/api/admin.ts`. Tests: per page, rendering by permission (absent buttons), happy paths, mapped errors, pagination.

## 6. Plan 05c — end-to-end, CSP, CI

- `apps/web/e2e/` with `@playwright/test` (pinned); `compose.e2e.yml` overlays `compose.yml`: Mailpit, loopback ports, `APP_ORIGIN=http://localhost`, secrets generated into a temp dir by `scripts/e2e-secrets.sh`; `pnpm test:e2e` at the root builds the images, starts the stack, waits for `/api/health/ready`, runs Playwright, tears down.
- Critical flow (one spec, sequential): `seed:admin` → accept the printed invitation link → sign in → enable TOTP (the test computes codes with `otpauth` from the shown secret) → create role "Readers" (`users.read`) → invite user B → read B's link from the Mailpit API → B accepts and signs in → B sees no Admin entry → `GET /api/admin/roles` from B's browser context answers 403 → admin suspends B → B's next navigation lands on `/`.
- Password reset flow through Mailpit.
- CSP (#9): the served `/` has no inline `<script>`/`<style>`, carries the CSP header, `/api/health/ready` through Caddy is 404 (RFC-10 R10); no `securitypolicyviolation` console errors during the flows.
- CI: job `E2E` in `ci.yml` (Docker on the runner), Playwright trace uploaded on failure; added to the `main` ruleset once stable (owner runs `scripts/github-admin.sh`).
